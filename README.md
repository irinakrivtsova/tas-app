# TAS — оценка студентов

Консольное приложение для ведения студентов, критериев оценивания и выставления оценок. Итоговая оценка считается как взвешенная сумма баллов по критериям.

## Запуск

Требуется Go 1.27.1 или совместимая версия.

```bash
go run ./cmd/tas
```

Сборка и проверка:

```bash
go build ./...
go test ./...
```

## Возможности

- добавление студентов;
- добавление критериев с максимальным баллом и весом;
- выставление оценки студенту по критерию;
- удаление выставленной оценки;
- таблица оценок по всем студентам и критериям;
- итоги по студентам с сортировкой по сумме;
- экспорт студентов в `.csv` или `.json`.

Главное меню:

```text
1. Студенты
2. Критерии
3. Выставить оценку
4. Удалить оценку
5. Таблица оценок
6. Итоги по студентам
7. Экспорт
0. Выход
```

## Архитектура

Приложение построено по принципам Ports & Adapters.

```text
cmd/tas
  └── точка входа

internal
  ├── domain
  │   ├── model      — сущности и value objects
  │   └── service    — доменные сервисы
  ├── application
  │   ├── ports      — узкие интерфейсы репозиториев
  │   └── usecase    — сценарии приложения
  └── infrastructure
      ├── container  — DI-контейнер на uber-go/dig
      ├── cli        — консольный адаптер
      ├── storage    — in-memory реализации репозиториев
      └── export     — CSV/JSON-экспорт
```

Зависимости направлены внутрь: `infrastructure → application → domain`. Домен не знает об инфраструктуре и use cases.

### Порты репозиториев

Порты собраны в `internal/application/ports` и разделены по ролям:

| Порт | Методы | Потребитель |
|---|---|---|
| `StudentSaver` | `Save`, `ExistsByID` | `AddStudentUseCase` |
| `StudentReadSaver` | `FindByID`, `Save` | `EvaluateStudentUseCase`, `RemoveEvaluationUseCase` |
| `StudentProvider` | `GetAll` | `GetReportUseCase` |
| `CriteriaSaver` | `Save`, `ExistsByName` | `AddCriteriaUseCase` |
| `CriteriaReader` | `FindByName` | `EvaluateStudentUseCase`, `RemoveEvaluationUseCase` |
| `CriteriaProvider` | `GetAll` | `GetReportUseCase` |

Memory-репозитории реализуют эти интерфейсы неявно и не импортируют пакет портов.

### Входной порт отчёта

`usecase.ReportReader` — входной порт для чтения готового отчёта:

| Порт | Методы | Потребитель |
|---|---|---|
| `usecase.ReportReader` | `GetStudents`, `GetCriteria` | `FileExporter`, CLI |

Интерфейс объявлен рядом с `GetReportUseCase`, потому что возвращает DTO этого же пакета. Если вынести его в `application/ports`, возникнет цикл `usecase → ports → usecase`. `GetReportUseCase` реализует порт неявно.

### DI / composition root

Сборка зависимостей вынесена в `internal/infrastructure/container` и построена на `uber-go/dig`. `container.New` регистрирует репозитории, доменный сервис, use cases, экспортёр и CLI; порты и интерфейсы CLI подключаются через `dig.As`, а `dig` лениво создаёт singleton-экземпляры. `container.BuildCLI` резолвит готовый `*cli.CLI`, поэтому `cmd/tas/main.go` только запускает приложение. Конфигурация CLI по-прежнему собирается функциональными опциями.

## DDD-модель

### Ubiquitous language

- **Студент** — кого оценивают.
- **Критерий** — за что ставят балл; у критерия есть максимум и вклад в итог.
- **Рубрикатор** — набор критериев, по которым оцениваются студенты.
- **Оценка** — факт «этому студенту по этому критерию поставили такой балл».
- **Итог** — результат по студенту, полученный из его оценок и рубрикатора, а не отдельная цифра.

### Сущности и value objects

- `Student` — aggregate root, хранит оценки студента.
- `Criteria` — отдельный агрегат/справочник критериев.
- `StudentID`, `StudentName`, `CriteriaName`, `Score`, `Weight`, `MaxScore` — value objects.
- `Evaluation` — value object внутри агрегата `Student`: связывает критерий и балл.

`Student` ссылается на критерий через `CriteriaName`, а не через объект `Criteria`. Благодаря этому границы агрегатов не размываются.

### Карта DDD

| Понятие | Код | Тип | Ответственность |
|---|---|---|---|
| Студент | `model.Student` | Entity / aggregate root | хранит имя и оценки студента |
| Критерий | `model.Criteria` | Entity | задаёт название, максимум и вес |
| Рубрикатор | `ports.CriteriaProvider`, `ports.CriteriaReader` | репозиторий-справочник | отдаёт критерии снаружи домена |
| Оценка | `model.Evaluation` | Value Object | связывает критерий и балл |
| Балл, вес, максимум | `model.Score`, `model.Weight`, `model.MaxScore` | Value Objects | хранят валидные числовые значения |
| Итог | `service.GradingService` | Domain Service | считает итог и максимальный итог |
| Сценарии | `usecase.*` | Application | координируют домен, репозитории и DTO |

### Ключевые решения

- `Student` — aggregate root: оценки меняются только через методы агрегата.
- `Criteria` — отдельный агрегат/справочник; `Evaluation` хранит `CriteriaName`, а не ссылку на `Criteria`.
- Проверка «критерий существует в рубрикаторе» выполняется в `EvaluateStudentUseCase`: это межагрегатный инвариант, для которого домену пришлось бы знать о репозитории.
- `StudentDTO` и `CriteriaDTO` используются только на границе приложения для CLI и экспорта; домен о них не знает.
- DI-контейнер собирает граф на краю приложения, а use cases зависят от портов, а не от конкретных адаптеров.

### Инварианты

- `StudentID >= 0`.
- `StudentName` и `CriteriaName` не могут быть пустыми или состоять только из пробелов.
- `Weight` находится в диапазоне `[0, 1]`.
- `MaxScore > 0`.
- `Score` находится в диапазоне `[0, MaxScore]` соответствующего критерия.
- `Evaluation` создаётся только из критерия, поэтому оценку нельзя создать «вне критерия».
- Конструкторы `NewStudent`, `NewCriteria` и `NewEvaluation`, а также `Student.AddEvaluation` отклоняют zero-value и невалидные значения, поэтому инварианты нельзя обойти через нулевые структуры.
- Репозитории не допускают дублирования идентификаторов студентов и имён критериев.
- Итоговая оценка и максимальный итог рассчитываются доменным сервисом `GradingService`.

### Domain service

`GradingService` рассчитывает:

- итоговую оценку студента как сумму `score * weight`;
- максимально возможный итог как сумму `maxScore * weight`.

## GoF-паттерны

| Группа | Паттерн | Где |
|---|---|---|
| Порождающий | Factory Function (Go-адаптация Factory Method) | `model.NewStudent`, `model.NewCriteria`, `model.NewEvaluation`, `cli.NewCLI` + функциональные опции |
| Структурный | Facade | `export.FileExporter` |
| Поведенческий | Strategy | `export.Formatter`, `CSVFormatter`, `JSONFormatter` |
| Поведенческий | Template Method (Go-адаптация через композицию) | `FileExporter.ExportStudents` + hook `Formatter.Write` |

Пояснения:

- **Factory Function** — это не классический Factory Method с наследованием, а идиоматичная для Go функция-конструктор. `NewStudent`, `NewCriteria` и `NewEvaluation` создают валидные объекты и возвращают ошибку при нарушении инвариантов. Боль: невалидный объект нельзя случайно создать в обход проверок. `NewCLI` задаёт значения по умолчанию, применяет функциональные опции и проверяет обязательные зависимости; функциональные опции — самостоятельный Go-приём, а не отдельный паттерн GoF.
- **Facade** — `FileExporter` скрывает от CLI получение отчёта, выбор форматтера, создание файла, запись и синхронизацию. Боль: CLI не разрастается инфраструктурной логикой экспорта и не знает о форматах и файловой системе.
- **Strategy** — формат вывода выбирается через интерфейс `Formatter`, реализации взаимозаменяемы. Боль: новый формат добавляется новой реализацией, без правок `FileExporter` и CLI.
- **Template Method** — в Go нет наследования, поэтому общий алгоритм `ExportStudents` задаётся композицией, а изменяемый шаг записи делегируется через интерфейс `Formatter.Write`. Это адаптация идеи Template Method, а не буквальная реализация через базовый класс. Боль: атомарная запись и обработка ошибок не дублируются между CSV и JSON.

Поведенческих паттернов ровно два, что не превышает ограничение «не более двух на группу».

## Сценарии

### Добавление критерия

Указываются название, максимальный балл и вес. Пустые названия отклоняются на уровне домена.

### Выставление оценки

Выбираются студент и критерий, затем вводится балл. Балл проверяется по максимальному значению критерия. Повторное выставление оценки по тому же критерию заменяет предыдущую без отдельного подтверждения.

### Удаление оценки

Выбирается студент, отображаются его текущие оценки, затем выбирается критерий и подтверждается удаление. Если оценки по критерию нет, операция завершается ошибкой.

### Экспорт

Поддерживаются `.csv` и `.json`. Формат определяется по расширению файла. В экспорт попадают оценки по критериям, итог студента и максимально возможный итог.

## Демонстрация

Сквозной сценарий:

1. Запустить приложение: `go run ./cmd/tas`.
2. Меню `2 → 1`: добавить критерии «Математика» (`max_score = 100`, вес `0.5`) и «Проект» (`max_score = 50`, вес `0.5`).
3. Меню `1 → 1`: добавить студентов с ID `1` («Иван Иванов») и ID `2` («Пётр Петров»).
4. Меню `3`: выставить Ивану «Математика = 80» и «Проект = 40».
5. Меню `6`: итог Ивана — `60.00`, максимальный итог — `75.00`.
6. Меню `7 → 1`: экспортировать в `students.csv`; в файле будут критерии, `Итог` и `Макс. Итог`.
7. Меню `3` повторно: заменить оценку по «Математика» на `90`; итог станет `65.00`.
8. Меню `4`: удалить оценку по «Математика»; итог снова станет `20.00`.

## Тесты

```bash
go test ./...
```

Покрыто:

- проверка пустых имён и value objects;
- отклонение zero-value `Student`, `Criteria`, `Evaluation`;
- создание `Evaluation` и проверка балла;
- добавление и удаление оценок в `Student`;
- запрет дублей студентов и критериев;
- расчёт итоговой оценки и максимального итога;
- удаление оценки через use case на memory-репозиториях;
- сортировка студентов и критериев при чтении из memory-репозиториев;
- атомарный экспорт в CSV/JSON и обработка ошибок записи;
- сборка графа зависимостей DI-контейнера и получение готового CLI;
- валидация зависимостей CLI и выход из приложения.

## Ограничения

- нет редактирования и удаления студентов;
- нет редактирования и удаления критериев;
- данные хранятся только в памяти и теряются после выхода;
- у оценки нет даты, комментария и автора;
- веса критериев не нормализуются автоматически;
- повторное выставление оценки по критерию заменяет её без подтверждения;
- удаление оценки необратимо;
- CLI не поддерживает аргументы командной строки и работает в интерактивном режиме.
